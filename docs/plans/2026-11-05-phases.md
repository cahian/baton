# Phases Implementation Plan

**Goal:** plan, build and review phases with a strong and a working model per provider, on top of the existing rotation and memory.

**Spec:** `docs/specs/2026-11-04-baton-design.md`, section "Phases: plan, build, review". It is the authority.

## Global Constraints

- Python 3.12 stdlib only. `uv run ruff check . && uv run ruff format --check . && uv run python scripts/check_private.py && uv run pytest -q` must pass.
- The rotation rule, the 90% guard, the Claude ledger, preemption and memory keep their behaviour. No test of them may be weakened to make this pass.
- Claude stays a fallback: review by another provider never brings Claude in while a plan agent is available.

## Review Focus

1. A job in flight from before this change, whose `state.json` has old-format `sessions` and no phase, resumes safely.
2. A preempted, killed, limited or failed round leaves the phase where it was, so the next agent repeats that work at the same tier.
3. A plan agent limited out during review with no other plan agent: same provider reviews; with both out, Claude reviews at its strong tier.
4. A malformed or missing `PLAN.md` or `REVIEW.md` cannot loop forever or crash: unknown verdict counts as `CHANGES` for the cycle cap; a round that wrote no plan means no tasks.
5. Stop, notes and `owes_round` behave as before in every phase.

### Task 1: the whole feature

**Files:** create `src/baton/phases.py`, `tests/test_phases.py`; modify `src/baton/config.py`, `src/baton/runner.py`, `src/baton/scheduler.py`, `src/baton/adapters/base.py` and the three adapters, their tests, `examples/defaults.toml`, `examples/goal.toml`, `README.md`.

**Config:**
- `AgentConfig` gains `build_model: str` and `build_effort: str`. `model` and `effort` remain the strong tier and today's plain-relay values.
- Defaults: codex `gpt-6.1-sol`/`medium`, build `gpt-6.1-terra`/`high`. antigravity `gemini-4-argon-medium`, build `gemini-3.8-flash-high`/`high` (its effort stays in the id, and `build_model` must start with `gemini-` too). claude_api `claude-opus-5-5`/`medium`, build `claude-sonnet-5-5`/`high`.
- `Goal.phases: bool = True`, a top-level `phases` key; add to `GOAL_KEYS`. A repository `baton.toml` may set it and the new `build_*` keys; they name models, not executables.

**Adapters:** `RoundContext` gains `tier: str = "strong"`, either `"strong"` or `"build"`. Each adapter builds its argv from a config for that tier, through one helper in `base.py`, `tier_config(cfg, tier)`, which returns `dataclasses.replace(cfg, model=cfg.build_model, effort=cfg.build_effort)` for build. Everything else (guard, ledger, budget, resume) is unchanged.

**`phases.py`:** pure functions, no I/O beyond reading the two files:
- `PLAN, BUILD, REVIEW` constants; `TIER = {PLAN: "strong", BUILD: "build", REVIEW: "strong"}`.
- `open_tasks(text: str) -> list[str]`, lines matching `^\s*- \[ \]`.
- `verdict(text: str) -> str`, first non-blank line starts with `APPROVED` (case-insensitive) gives `"approved"`, anything else `"changes"`.
- `@dataclass class PhaseState: phase, base, cycles, stuck, last_open`, with `to_json` and `from_json` tolerating missing or bad data by returning the start state.
- `advance(state, *, outcome_completed: bool, open_now: list[str], review_text: str, max_cycles: int = 3) -> tuple[PhaseState, bool]`: the transition table from the spec; the bool means "end of cycle reached". A round that did not complete changes nothing.
- `phase_prompt(phase: str, next_task: str, base: str) -> str`: exact instructions for each phase, naming the files, stating one task only in build, and in review that it must not edit code and must inspect `git diff <base>..HEAD`.

**Scheduler:** `pick(avoid: str | None = None)`: when `avoid` is the agent it would return and another plan agent is available, return that one for this round without changing the rotation's `current`, so the next non-review round continues as before. Never returns a metered agent because of `avoid`.

**Runner:**
- `_Run` holds a `PhaseState`, persisted in `state.json`, only when `goal.phases`. With `phases = false`, behaviour is byte-for-byte today's.
- `need_gate` is set only at end of cycle. A gate failure sets phase `PLAN`, `cycles = 0`, keeps the base. Pass finishes as today. With no verify command, end of cycle finishes the goal.
- Fresh job, or `owes_round`: phase `PLAN`, `base` = current head.
- `build_prompt` gets the `phase_prompt` block. It is added for fresh and resumed rounds.
- `RoundContext.tier` from `TIER[phase]`.
- Sessions keyed `f"{agent}:{role}"` (`plan`, `build`). Review passes no session and stores none. An unknown old key is ignored, so the agent starts fresh.
- For review, `self.sched.pick(avoid=<agent of the last build round>)`.
- Emit `phase` events with `phase`, `cycle`, `reason`; show one short line in the OpenCode stream through `gateway.py`.
- The `round_end` event and memory pages include `phase`.

**Docs:** README: a "Phases" section after "The rotation", the table, `phases = false`, and one Quick start sentence saying a small request is answered in one round. Examples updated.

**Tests:** table tests of `advance` for every transition, including each Review Focus line; runner tests with fake adapters for a full cycle (plan, two builds, review changes, build, review approved, gate), a stuck builder, a failed gate returning to plan, the review going to another provider without moving `current`, and a resumed old-format state; per-adapter argv tests for both tiers; `phases = false` keeps today's argv and flow. Existing runner tests that assume the plain relay should set `phases = false` in their goal fixture rather than be rewritten.

Do not commit. Leave changes in the working tree.
